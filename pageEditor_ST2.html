Splash Screen


Technical Description

The splash screen is structured using semantic HTML elements to organise the content. Here, the main element is the main container, and the section elements are used to group the content, such as the title, mission, members, loader, countdown and button. That helps to improve readability and maintainability. The h1 tag is used for the main website title to create a clear heading hierarchy, and the h2 tag is used for supportive headings. The span element is used inside a heading, which allows to style specific part of the text. The img tag is used to display the logo and the p elements are used to display team member names. The button element provides an opportunity for user interaction for skipping the splash screen, and the span inside the countdown updates the time dynamically using JavaScript. The meta http-equiv="refresh" content="4; url=home.html" tag automatically redirects the user to home.html after 4 seconds, which is useful for creating splash screens.


CSS mainly focus on positioning, layout, and visual design. Flexbox (display:flex) is used in the .topic and .members sections to align horizontally. Furthermore, control spacing and positioning using justify-content, align-items and gap. The flex-wrap property ensures responsiveness on smaller screens. A full-screen background image is applied using background-size: cover, background-position: center, and background-attachment: fixed for a consistent visual effect. A dark overlay is created using the ::before pseudo-element combined with position: fixed and z-index to ensure content appears above it. Colors, spacing, font styles, and border-radius improve readability and style. The loader uses border, border-radius, and @keyframes spin for animation. The button has transition and :hover for interactivity. JavaScript powers the countdown and skip button. The updateCountdown function decreases the timer each second using setTimeout. The skip button uses an event listener to redirect users to the home page immediately.


Accessibility

Accessibility was considered by using semantic HTML elements such as main and section, which help screen readers understand the page structure. Proper heading usage (h1 and h2) improves navigation and readability for assistive technologies. The image includes descriptive alt text (“Website logo”), which helps visually impaired users to understand its purpose. There is a good colour contrast between white text and the dark background overlay, which makes the text clearer and more readable. Users can access the skip button using the tab key and activate it using the enter key, making the page usable without a mouse. Countdown is displayed as text, ensuring users can understand the timing before redirection. Moreover, the automatic redirect using the meta tag provides an alternative way to proceed, while the skip button gives users control. Overall, these techniques improve usability and ensure the page is accessible to a wider range of users, including those using keyboards or assistive technologies.

Action Impact Simulator


Technical Description

The page is built using HTML5 semantic tags to define a clear document outline. The main section holds the simulator content, such as top introduction and card based layout for user actions. Each action is placed inside a section class = "card" with a data-impact attribute to store its value, which are later used in JavaScript calculations. Headings (h2, h3) are used to create a clear content hierarchy, while p elements display descriptions and results. Images are added using the img tag inside each card. The alt attribute is included to describe the image content. The feedback area is grouped inside .feedbackContainer, where span elements are used to dynamically display total points, selected actions, impact level, and feedback. A button is used for resetting the simulation


Cards are styled with fixed width and height to maintain consistency. The .selected class highlights chosen cards using border, box-shadow, and filter, and a transform: scale() effect is added on hover to improve interactivity. . The ::after pseudo-element is used to display a ''Selected'' label on chosen cards. Different background styles (low-bg, medium-bg, high-bg) are applied dynamically based on the user's score. These use background-image, background-size: cover, and background-attachment: fixed to create a full-screen effect. A dark overlay is added using the ::before pseudo-element with position: fixed and z-index to improve text readability. Smooth transitions are added using transition for background changes. The feedback container is styled using box-shadow, border-radius, margin and padding to make it nice and smooth. Colour styles such as lowText, mediumText, and highText represent different impact levels using different text colors and box shadows. JavaScript adds interactivity to the page. Event listeners detect when a card is clicked and toggle the selected class. Functions like updateTotalPoints(), updateImpactLevel(), and updateFeedback() calculate and display results dynamically using the data-impact values. The reset button clears all selections and resets the interface. Background changes are also controlled through JavaScript based on the total score.


Accessibility

Every image contains descriptive alternative text that allows screen reader users to understand the context of the action cards. Furthermore, to improve readability over background images, a semi-transparent dark overlay was added using the ::before pseudo-element. This increases the contrast between text and the background. Apart from that, Selected cards are not only indicated by colour alone, but they also display a ''Selected'' badge and a different border style. This helps users, including those with colour vision difficulties, clearly understand the selection. The reset button is standard HTML button element, which can be accessed using the keyboard (Tab and Enter keys), supporting keyboard navigation. Furthermore Feedback such as total points, impact level, and messages are shown as text, making it easier for screen readers to interpret. And The page layout works on different screen sizes, helping users access content on mobile and desktop devices.

Content Page

Technical Description

The content page is structured using semantic HTML elements to create a clear and organized layout. The main element holds the primary content, which is divided into multiple section elements. Each section represents a specific topic such as Introduction, Nutrients, and Conclusion, using unique id attributes to support internal navigation. A navigation block at the top (.main-section) uses anchor links (href="#section-id") to allow users to quickly jump to different parts of the page. Headings such as h1 and h2 are used in a proper hierarchy to improve readability and structure. Images are included using the img tag with descriptive alt text, supporting both content understanding and accessibility. Furthermore, p tags are used for the text. Links are added using a tags for internal navigation or external references. A 'Go to Top' button is also included so users can easily scroll back to the top of the page.


The .main-section class is centered using margins and fixed width, while links are styled as block elements to appear like buttons. Borders, border-radius, and box-shadow are applied to content containers and images to make it neat and smooth. Images use object-fit: cover to maintain proper proportions and prevent stretching and Images are centered using display: block and margin: auto. Hover effects with transform: scale() on links, buttons, and section anchors provide visual feedback and make interactive elements more noticeable. Furthermore, pseudo-elements like ::after are used to add arrows to section links. The .top-btn uses position: fixed to remain visible while scrolling, improving navigation on long pages. Box shadows, borders, and consistent colour usage (blue theme) create visual consistency. Overall, the CSS combines positioning, spacing, colour, hover effects, box shadows, and pseudo-elements to create a structured, visually consistent, and user-friendly design.


Accessibility

HTML elements such as header, nav, main, and section are used to clearly structure the page, which helps screen readers understand and navigate the content easily. Using proper heading hierarchy helps to improve navigation for users. Furthermore, all images contain alt text such as "balanced meal plate" and "healthy vs junk food", so users who can not see the images can still understand it's meaning using screen reader. The "Go to Top" button improves navigation for long pages, reducing the need for excessive scrolling. Internal navigation links make it easier for users to jump between sections. Moreover, color contrast is maintained by using dark text on white smoke background. That makes the content more readable. Hover effects provide visual feedback for interactive elements, helping users recognize clickable items. Additionally, link states such as hover, visited, and active are styled differently, which improves clarity and usability. HTML elements like "a" and "button" are used. Therefore, users can navigate the page using the keyboard (such as the Tab key). The page layout adapts to different screen sizes, which helps users to access the content using different devices.

Challenges and Lessons Learned


In the process of developing the Splash Screen, Action Impact Simulator (AIS) and Content Page, a number of challenges arose. These problems assisted me in enhancing my problem-solving skills and web development knowledge.


While creating the splash screen, I faced a few challenges. I wasn't sure how to use the meta refresh tag to redirect the page. I learned it from W3Schools, which helped me synchronise the redirect with a countdown timer. From this, I learned how to use meta refresh tag properly. Furthermore,It was difficult to make the text clear against the background, as the text was initially mixed with the image. I added a semi-transparent dark overlay using the ::before pseudo-element and controlled the layers using z -index. This improved the readability. Here, I learned the importance of contrast and readability in web design. Not only that, creating a loading animation was another challenge. I used CSS keyframes to animate a loader, which showed the users that the page was loading. This helped me to understand how animation can improve the user experience. I had to set the correct timing and update the countdown dynamically. Initially, the timing could not update properly. Then, I used JavaScript setInterval() for the countdown update every second. This taught me how JavaScript can be used to create interactive and dynamic web pages.


In the Action Impact Simulator (AIS), one of the biggest challenges was handling many updates at the same time. As an example, highlighting the card, updating total points, showing the impact level, changing feedback, and updating the background. Initially, these did not work together properly; however, I solved this by creating separate functions for each task, calling them inside the click event. I learned how to break a complex problem into smaller functions and solve it. Another challenge was getting the correct impact point value from each card because each card has a different value. I solved this by using the data-impact attribute to store the points in HTML and retrieve them using getAttribute(). This helped me to understand how HTML and JavaScript can work together to handle data. Furthermore, identifying which cards are selected or unselected when the user clicks them. I solved this by using JavaScript add and remove class using this.classList.toggle('selected'). This allowed me to track selected and unselected cards and use them for calculations and styling. From this, I learned how to dynamically add and toggle classes using JavaScript to control both design and functionality.


For the content page, the main challenge was creating the “Go to Top” button. I managed to solve this by using an anchor link (#top) and CSS position: fixed to keep the button visible while scrolling. From this, I learned how to use internal links and positioning to improve navigation.


Overall, these challenges helped me learn to debug issues, write code in a better way, and how to combine HTML, CSS, and JavaScript effectively.
